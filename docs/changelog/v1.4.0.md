# v1.4.0 — 2026-10-15

Minor release. Previous: [v1.3.0](v1.3.0.md) · Next: [v1.4.1](v1.4.1.md) · Diff: `git log v1.3.0..v1.4.0`

## Features

- Phone assistant integration with Gooyai, an AI phone receptionist (#20, #21). Each clinic
  connects its own Gooyai account from the dashboard (Settings → Phone assistant).
  - Connection: `GET`, `PUT` and `DELETE /meets/phone-assistant/connection`. A saved key is
    checked against Gooyai first; a rejected key returns `INVALID_ARGUMENT` and nothing is
    stored. Responses never include the key, only `key_last4`, the environment
    (`sandbox` or `prod`) and `updated_at`. Leaving `api_key` empty keeps the stored key, so
    a clinic can change only the environment or proxy.
  - Per-clinic proxy (`proxy_url`: http, https, socks5 or socks5h). The password is masked
    as `****` in responses, and sending `****` back keeps the stored one.
  - Incoming calls: `GET /meets/calls`, filtered by date range, phone and `should_recall`,
    paginated up to 100 per page; and `GET /meets/calls/{id}`. `direction=outgoing` is
    accepted but returns `UNIMPLEMENTED` (HTTP 501), because Gooyai has no outgoing calls
    API yet.
  - `GET /meets/phone-assistant/providers` lists the clinic's Gooyai providers.
  - The key is sealed with AES-256-GCM and stored in the clinic's user settings
    (`settings.phone_assistant`) on the identity (auth) service, written with the caller's
    own token. Only the ciphertext leaves this service.
  - The HTTP routes say `phone-assistant`, not the vendor name, because the dashboard is
    white-label.
  - A clinic that isn't connected, or whose key Gooyai rejects, gets
    `FAILED_PRECONDITION`, never `UNAUTHENTICATED`, so the dashboard doesn't log the
    user out.
- `pkg/gooyai`: a standalone Gooyai Partner API client that other services can reuse. It
  also covers providers, slots and bookings, which this release doesn't expose yet. It
  retries GETs on 5xx and transport errors only, never writes, because a retried POST
  could double-book.

## Fixes

- Listing calls failed to decode: Gooyai's live API sends `call_forward` and
  `should_recall_user` as `0`/`1` instead of the documented booleans. Both are accepted now.

## Deployment

New environment variables (see `.env.example`):

| Variable | Notes |
|---|---|
| `GOOYAI_BASE_URL` | Defaults to `https://api.gooyai.ir`. |
| `USERS_SERVICE` | Base URL of the identity (auth) service, which owns users and stores each clinic's encrypted key. Meet calls `GET`/`PUT {USERS_SERVICE}/users/{uuid}` and `GET {USERS_SERVICE}/me` on it. Unlike `AUTH_SERVICE`, it has no `/auth` suffix. Unset disables the integration. |
| `GOOYAI_ENCRYPTION_KEY` | Base64 of exactly 32 bytes (`openssl rand -base64 32`). Unset disables the integration; a malformed value stops startup. Rotating it makes stored keys unreadable, so clinics would have to re-enter theirs. |
| `GOOYAI_PROXY` | Default proxy for clinics without their own. Unset falls back to `HTTPS_PROXY` etc.; a malformed value stops startup. |

The identity service must keep `phone_assistant` in a user's settings. If it only accepts
listed settings keys, `phone_assistant` must be on that list; otherwise it silently drops the
write, and saving a connection fails.

No migrations.
